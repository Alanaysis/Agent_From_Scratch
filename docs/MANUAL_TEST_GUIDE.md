# IRG 手动测试指南

> 本文档覆盖单元测试无法覆盖的功能点，需要通过 GUI 进行手动验证。
> 测试环境：远程访问 `http://<ip>:3001`（Electron GUI）

---

## 前置条件

1. 后端服务已启动：`npm run dev:electron` 或 `npm run dev:gui`
2. LLM 已配置（Settings 页面）
3. 浏览器可以访问 `http://<server-ip>:3001`

## 二、聊天图片理解（Multimodal Chat）

### TC-M01：粘贴图片
- **步骤**：Chat 页面 → 在输入框 Ctrl+V 粘贴一张截图
- **预期**：
  <!-- - [ ] 输入框上方出现图片预览缩略图（48x48） -->
  <!-- - [ ] 缩略图右上角有 × 按钮 -->
  <!-- - [ ] 输入框 placeholder 文字包含 "paste images" -->

### TC-M02：移除待发送图片
- **步骤**：粘贴图片后 → 点击缩略图上的 ×
- **预期**：
  <!-- - [ ] 图片预览消失 -->
  <!-- - [ ] 可以继续粘贴新图片 -->

### TC-M03：发送带图片的消息
- **步骤**：粘贴图片 → 输入 "描述这张图片" → 点击 Send
- **预期**：
  - [ ] 用户消息立即显示（不等待流结束）
  - [ ] 用户消息中图片以缩略图形式显示（最大 200x200）
  - [ ] 图片下方显示文字
  - [ ] 助手回复引用了图片内容

### TC-M04：纯文字消息（回归测试）
- **步骤**：不粘贴图片 → 输入 "hello" → 发送
- **预期**：
  - [ ] 消息正常发送和显示
  - [ ] 无图片相关 UI 出现

### TC-M05：多张图片
- **步骤**：连续粘贴 3 张不同图片 → 发送
- **预期**：
  - [ ] 3 张图片预览都显示
  - [ ] 可以单独移除某一张
  - [ ] 发送后 3 张图片都显示在用户消息中

### TC-M06：历史 Session 图片显示
- **步骤**：发送带图片的消息 → 切换到其他页面 → 回到 Chat → 选择该 session
- **预期**：
  <!-- - [ ] 历史消息中的图片仍然正确显示 -->
  <!-- - [ ] 图片缩略图可以正常加载 -->

## 三、Session 状态

### TC-S01：新建 Session 状态
- **步骤**：Chat → 发送第一条消息
- **预期**：
  <!-- - [ ] Sessions 页面显示新 session -->
  <!-- - [ ] 状态为 "Active"（绿色） -->

### TC-S02：Session 完成状态
- **步骤**：发送消息 → 等待助手回复完成
- **预期**：
  - [ ] 状态变为 "Completed"（蓝色）
  - [ ] Summary 显示 "done · ..."

### TC-S03：Session 错误状态
- **步骤**：让工具执行出错（比如读取不存在的文件）
- **预期**：
  - [ ] 状态变为 "Error"（琥珀色）
  - [ ] Summary 显示 "⚠️ N errors"

### TC-S04：Session 超时降级
- **步骤**：创建一个 session → 等待 1 小时不操作
- **预期**：
  - [ ] 状态从 "Active" 降级为 "Idle"

### TC-S05：Session 排序
- **步骤**：创建多个不同状态的 session
- **预期**：
  - [ ] Error 排最前
  - [ ] Active 次之
  - [ ] Completed 再次
  - [ ] Idle 排最后
  - [ ] 同状态按时间倒序

## 六、Hook 系统

- **步骤**：执行一个会报错的命令（如 `read nonexistent.txt`）
- **预期**：
  - [ ] `.irg/knowledge.json` 中新增一条 anti_pattern
  - [ ] 内容包含错误信息和工具名

- **步骤**：同一个工具连续报错 3 次
- **预期**：
  - [ ] knowledge.json 新增 "failed 3 times" 的 anti_pattern

### TC-H03：效率模式记录
- **步骤**：一个 session 中使用 Read 工具 15 次以上
- **预期**：
  - [ ] knowledge.json 新增 "15+ times" 的 pattern

- **步骤**：Chat → 发送 "你好"
- **预期**：
  - [ ] 助手正常回复
  - [ ] 流式输出正常
  - [ ] 消息计数更新

- **步骤**：Chat → "列出当前目录文件"

## 十、边界与异常场景

### TC-E01：长对话上下文压缩
- **步骤**：在一个 session 中持续对话 20+ 轮
- **预期**：
  - [ ] 不会因为上下文溢出报错
  - [ ] 对话质量不会严重下降

### TC-E02：网络断开
- **步骤**：断开浏览器网络 → 发送消息
- **预期**：
  - [ ] 显示错误提示
  - [ ] 不会卡死

### TC-E03：LLM 未配置
- **步骤**：清空 API Key → 发送消息
- **预期**：
  - [ ] 显示 "LLM is not configured" 错误

### TC-E04：并发任务
- **步骤**：同时分配 3 个任务
- **预期**：
  - [ ] 任务按优先级顺序执行（maxConcurrentTasks=1）
  - [ ] 不会死锁
